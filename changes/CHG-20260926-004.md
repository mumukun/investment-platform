# Change

## Change ID

`CHG-20260926-004`

## Title

新增实时涨停天梯与近期交易日查询

## Status

`RELEASED`

方案已于 2026-09-26 获用户确认；实现、自动化验证、主分支合并和分支清理已完成，已纳入正式发布候选。

## Description

为 Investment Research Dashboard 新增“涨停天梯”页面，展示当日盘中实时更新的涨停股票，并可查询至少最近 5 个实际交易日的收盘快照。

目标范围：

- 按连板高度从高到低分级展示，并在每一级内按行业分组。
- 显示主板、创业板、科创板、北交所及其当日有效涨跌停幅度；除 10cm、20cm、30cm 外，ST 股票应诚实显示 5cm。
- 显示首次封板时间、末次封板时间、炸板次数、封单金额、一字板、连板数等可验证事实。
- 显示带来源与质量标识的涨停原因；在没有可信原因源时返回空值，不把题材关联或模型推断伪装成事实。
- 点击股票名称后打开详情抽屉，复用现有基础资料、公司资料和日 K 线能力，并以所选历史交易日作为 K 线截止日。
- 当前交易日页面显示数据更新时间、健康度和是否陈旧；历史日期读取持久化快照，不在读请求中访问第三方数据源。

非目标：

- 不改造现有飞书“涨停天梯”报表。
- 不在本 Change 中引入盘中分时 K 线、逐笔成交、涨停预测或自动交易能力。
- 不让 `marketNewsFeed` 参与第一阶段；关联题材可复用 `stock-analyzer` 已有分类事实。
- 不在方案确认前创建业务仓库分支、修改业务代码、连接生产、回填生产数据或发布。

验收标准：

1. 当日交易时段内，页面可消费 `stock-analyzer` 约 5 分钟一次的最新持久化快照，且明确展示最后成功更新时间。
2. 可选择最近至少 5 个实际交易日；周末、节假日和指定非交易日按数据库中真实可用交易日解析，不能用自然日减法代替。
3. 每只股票显示代码、名称、行业、板块、有效涨跌停比例、连板数、首次/末次封板时间；存在数据时显示炸板次数、封单额、近期涨停统计和原因。
4. 无限制交易日的新股不进入普通涨停天梯；ST 5cm、主板 10cm、创业板/科创板 20cm、北交所 30cm 均由每日 `security_trade_rule` 权威规则判定。
5. 点击股票名称可打开基础信息、公司资料与截至所选日期的日 K 线；历史详情不得混入未来行情。
6. 上游超时、空数据或部分字段缺失时，Dashboard 显示陈旧/部分可用状态，不把异常空结果展示成“当日无涨停”。

## Dependency Impact

数据链路：

`东方财富涨停池（经 AkShare）` → `stock-analyzer` 定时采集/规则归一化 → `limit_up_snapshot` → 版本化 Integration API → `investment-research-dashboard` adapter/API → 涨停天梯页面与股票详情抽屉。

- `stock-analyzer` 是 Provider，`investment-research-dashboard` 是 Consumer。
- 正式发布顺序必须是 Provider → Consumer；Feature Flag 在 Provider 健康与契约测试通过后才启用。
- 当前实现已经由 `hotmap_cache` 在交易时段约每 5 分钟采集全市场与涨停池并写 PostgreSQL，设计复用该调度，不在 Dashboard 请求链路同步抓取第三方数据。
- 当前 AkShare `stock_zt_pool_em` 数据包含首次/末次封板时间、炸板次数、封板资金、近期涨停统计、连板数和行业，但不包含可直接验证的涨停原因；原因需要独立可信数据源与来源标识。

## API Impact

新增 Provider 端点：

`GET /api/integrations/investment-dashboard/limit-up-ladder?observation_date=YYYY-MM-DD&days=5`

- Bearer 认证沿用现有 Investment Dashboard Integration API。
- `observation_date` 可选，默认北京时间当日。
- `days` 默认 5，建议允许 1–20；返回不晚于观察日的真实可用交易日。
- 查询只读 PostgreSQL，不发起第三方网络请求，不因历史查询改写快照。

建议响应骨架：

```json
{
  "ok": true,
  "contract_version": "investment-dashboard-limit-up-ladder-v1",
  "rules_version": "limit-up-ladder-rules-v1",
  "observation_date": "2026-09-25",
  "actual_trade_date": "2026-09-25",
  "generated_at": "2026-09-25T14:55:00+08:00",
  "timezone": "Asia/Shanghai",
  "available_trade_dates": ["2026-09-25", "2026-09-24"],
  "source_status": {
    "status": "fresh",
    "source": "eastmoney_limit_up_pool",
    "is_mock": false,
    "last_success_at": "2026-09-25T14:55:00+08:00",
    "issues": []
  },
  "days": [
    {
      "trade_date": "2026-09-25",
      "snapshot_time": "2026-09-25T14:55:00+08:00",
      "market_status": "盘中",
      "quality": "fresh",
      "summary": {
        "limit_up_count": 42,
        "max_streak": 5,
        "one_word_count": 3,
        "by_streak": {},
        "by_board": {},
        "by_limit_pct": {}
      },
      "items": []
    }
  ]
}
```

每个 `item` 至少包含：

- 标识与行情：`code`、`name`、`close`、`change_pct`、`amount_yi`、`turnover_pct`。
- 交易制度：`exchange`、`board`、`price_limit_pct`、`is_st`、`is_no_limit_day`。
- 行业分类：`industry_l1`、`industry_l2`、`industry_taxonomy`、`industry_effective_date`、`industry_quality`。
- 涨停事实：`limit_streak`、`first_limit_at`、`last_limit_at`、`break_count`、`seal_amount_yi`、`recent_limit_stats`、`is_one_word_limit`。
- 原因语义：`limit_reason`（可空）、`reason_kind`（`provider_fact` / `inferred_context` / `unavailable`）、`reason_source`、`reason_evidence`、`reason_quality`。
- 数据质量：`quality`、`issues`。所有时间使用带 `+08:00` 的 ISO 8601；前端可格式化为 `HH:mm:ss`。

Dashboard 新增对外只读端点，沿用现有 `/api/v1` 投影与错误语义。股票详情建议新增语义中立的别名：

- `GET /api/v1/limit-up-ladder`
- `GET /api/v1/stocks/{code}/candles?end_date=YYYY-MM-DD&days=60`

Provider 的中立 K 线别名继续返回现有 `investment-dashboard-swing-candles-v1`，旧的 short-selection/swing-selection 端点保持不变；若开发评估不值得增加别名，新页面可复用现有通用实现，但不得复制 K 线计算逻辑。

## Database Impact

建议新增领域表 `limit_up_snapshot`，而不是继续给约 5000 只股票的 `a_share_snapshot` 添加只对涨停池有意义的列。

建议字段：

- 主键：`(trade_date, code)`。
- 采集：`snapshot_time`、`source`、`source_payload_version`、`quality`、`issues`。
- 股票/分类：代码、名称、交易所、板块、行业一级/二级及分类元数据。
- 交易规则：`price_limit_pct`、`is_st`、`is_no_limit_day`、当日涨停价。
- 涨停事实：价格、涨幅、成交额、换手率、连板数、首次/末次封板时间、炸板次数、封单额、近期涨停统计、一字板。
- 原因：可空的原因、来源、证据、质量与生成方式。

数据阶段：

1. Add：新增表与索引；不改现有表和读路径。
2. Backfill：开发完成后提供带 dry-run 的最近交易日回填命令；任何生产回填需要独立明确授权。
3. Migrate Read/Write：现有 `hotmap_cache` 每轮完成涨停池归一化后，在单个交易日范围内事务更新最新集合。
4. Verify：核对交易日、总数、板块/涨停比例、最高连板和源数据质量。
5. Remove Later：本 Change 不删除旧字段或飞书报表路径。

当前日期的刷新应保持历史交易日不可变。实现阶段需在以下方式中选择并通过并发测试：

- 推荐：以 `snapshot_run_id` 保存每轮集合，并为每个交易日选最新成功轮次；收盘后标记 final。该方式能保留盘中演化且避免“先删后插”的空窗。
- 最小方案：事务内仅替换精确 `trade_date` 的集合；不得使用模糊日期或跨日删除。

UI 只要求近期 5 个交易日，存储建议保留至少 20 个交易日，便于节假日容错、质量审计和后续趋势能力。

## Contract Impact

新增独立契约：

- `contract_version`: `investment-dashboard-limit-up-ladder-v1`
- `rules_version`: `limit-up-ladder-rules-v1`
- Producer: `stock-analyzer`
- Consumer: `investment-research-dashboard`

契约规则：

- Consumer 必须严格接受已支持的 `contract_version`，拒绝未知主版本或结构。
- `rules_version` 用于可追溯性，不应被 Consumer 写死为业务门禁。
- 枚举、单位、时区、空值与 quality/issues 语义必须写入 fixture。
- `limit_reason = null` 表示无可信事实；`related_themes` 如展示，必须标记为“关联题材”，不能改名为“涨停原因”。
- 可选原因字段的新增只有在 Consumer 容忍字段缺失/空值时才视为向后兼容。
- 现有 `investment-dashboard-swing-candles-v1` 响应契约不变；只增加中立路由别名时不升级其契约版本。

## Compatibility Strategy

整体为向后兼容的 Add：新增表、新 API、新页面，不修改或移除现有端点、飞书报表与已有 Dashboard 功能。

- Provider 可以先部署并保持新功能未激活。
- Consumer 在契约可用后部署；Feature Flag 默认关闭。
- 原因字段允许为空，因此可信原因数据源可以作为后续小阶段接入而不阻塞核心天梯上线。
- 行业分类与交易规则都返回来源和有效日，避免 Consumer 根据代码自行推断板块或涨停幅度。

## UI Design

主页面采用“行业 × 连板高度”的二维矩阵：行业为行、动态连板高度为列，最高连板在左。矩阵表头和行业列吸附，宽屏充分利用空间，窄屏横向滚动；单元格使用紧凑股票条目，避免纵向卡片造成大面积留白。

页面结构：

1. 顶部：交易日选择器（最近至少 5 个真实交易日）、盘中/收盘状态、最后更新时间与质量徽标。
2. 摘要：涨停总数、最高连板、一字板数、行业数，以及 5cm/10cm/20cm/30cm 分布。
3. 筛选：板块/涨停比例、连板数、行业、首次封板时间段、一字板、股票名称/代码。
4. 天梯：行业按最高连板和涨停家数排序，连板列按最高板向首板降序；单元格条目显示板块与 cm 徽标、首次/末次封板时间、炸板次数、封单额、原因或关联题材。
5. 详情抽屉：基础行情、所属板块/行业、公司资料、截至所选交易日的日 K 线；复用 `SwingCandlestickChart` 与 `CompanyProfilePanel`。

当前交易日建议前端 30–60 秒刷新 Dashboard API；Provider 仍按现有约 5 分钟调度更新，因此 UI 明示源更新时间，避免制造秒级实时的错觉。
