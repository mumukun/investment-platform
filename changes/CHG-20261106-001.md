# Change: CHG-20261106-001

## Title / Status
波段结算明细分页与短线、波段模拟跟踪统一 / RELEASED（REL-20261106-002）

## Description
效果跟踪的「结算状态」按钮默认打开该策略最近五个实际交易日。当前 history-v3 抽屉首屏请求 50 条，翻页和状态筛选由服务端执行。上方全历史汇总继续使用独立接口；抽屉显示当前日期范围和筛选后总数。主动选择完整历史后，原日期、策略及状态筛选继续生效。history-v2 保留原接口和分页行为。

模拟跟踪首屏按最近已结算、跟踪中、新买入排序。已结算按结算日查最近五个交易日；跟踪中与新买入按买入日查最近五个交易日。跟踪中显示最新一期累计收益及缺口；等待首个收盘的名单按买入日折叠。短线当前收盘模拟账本使用相同的三张可展开表格，按原次日结算口径展示。短线与波段的完整历史仍需主动切换。

## Tests

105 项定向后端测试、44 项页面测试、3 项代理契约测试及前端构建通过。隔离 PostgreSQL 对照 196 笔近期、4 笔较早记录，后端中位耗时从旧全历史 92.0 ms 降至新首屏 34.9 ms，前两页逐条匹配旧结果。Chrome 用模拟数据点击「趋势通道结算明细」，首屏 50/196、第二页 50 条，切换完整历史共 200 条。浏览器模拟点击约 242 ms，仅供本地参考。

首屏布局追加验证通过。107 项后端、45 项页面、3 项代理契约测试及构建通过；本地 Chrome 验证最近已结算排在前面、逐日结果可展开、跟踪缺口提示和 196 笔模拟新买入默认折叠。

短线布局追加验证通过。隔离 PostgreSQL 26 项通过，覆盖收盘前后分组及买入日早于窗口的近期结算。Dashboard 8 项短线组件测试、代理契约、类型检查与前端本地构建通过。Chrome 使用合成数据验证三张表表头一致、179 笔新买入默认折叠和名单展开。

短线查询提速使用本地隔离 PostgreSQL 和合成账本。5,984 笔记录、7 次交替测量中位值，完整历史首页 60.6 → 39.1 ms，带筛选翻页 54.1 → 41.4 ms，近期跟踪中 74.0 → 44.9 ms。17,996 笔时分别为 136.6 → 116.7 ms、115.2 → 99.5 ms、151.6 → 102.1 ms。分页、总数、批次及越界结果与优化前逐项一致。定向后端 26 项、短线组件 8 项及前端类型检查通过。
