# Change

## Change ID

`CHG-20260926-000`

## Title

Exact Tag Deployment Governance

## Status

`IN_PROGRESS`

## Change Type

`OPERATIONAL_DEPLOYMENT_TOOLING`

Business Feature: **NO**

## Description

Make each business repository's production deployment entry fail closed unless an explicit immutable
`vMAJOR.MINOR.PATCH` Tag is supplied, resolve that Tag to an exact Commit, verify it is reachable from
`origin/main`, and deploy only that exact source identity.

Acceptance criteria:

- no deployment entry defaults or falls back to `main`, `HEAD`, `latest`, or `origin/main`;
- absent, malformed, missing, or off-main Tags fail before checkout, build, restart, migration, or deploy;
- annotated and lightweight Tags resolve through `<tag>^{commit}`;
- production checkout is detached at the resolved Commit and unexpected tracked dirt blocks execution;
- safe `--help` and `--dry-run` validation is available;
- existing Compose, health/status, stock-analyzer configuration/backfill, Dashboard metadata, and NAS
  launcher behavior remain intact after the identity gates.

Non-goals: business logic, API behavior, database schema/data, application versions, formal Release
Tags, Production deployment, registry promotion, CI/CD, and Production baseline discovery.

## Dependency Impact

## API Impact

## Database Impact

None. The deployment scripts do not add or modify schema/data behavior in this Change.

## Contract Impact

Adds an operational deployment-entry contract: production input is an explicit immutable SemVer Tag;
identity is Tag plus exact Commit SHA; rollback input is an explicit previous Tag. No business
`contract_version` or `rules_version` changes.

## Compatibility Strategy

The new production interface intentionally fails closed for prior no-argument/main-based invocation.
Existing repository-specific build, Compose, health, metadata, backfill, and restricted NAS launcher
implementation is preserved behind the new identity validation gates.
