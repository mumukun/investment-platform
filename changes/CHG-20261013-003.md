# Change: CHG-20261013-003

## Title / Status

升级请求客户端恢复 CTEE 原站采集并降低请求频率 / RELEASED

## Description

用户要求恢复 CTEE 原站采集与推送，允许降频，不接受 Google News 标题索引降级。
旧 curl_cffi 0.13.0 的默认 Chrome 136 请求配置在同一群晖代理出口返回 403/challenge；
升级至 0.16.3 的 Chrome 150 配置返回 200。真实项目函数读取半导体频道 15 篇近期文章，
linux/amd64 Python 3.13 的隔离镜像读取即时科技频道 45 篇。保留原站 API content、发布时间
和 ctee:{articleID} 去重语义，不增加浏览器服务或第三方新闻源。此次对照实验确认客户端升级
恢复已测试的链路，未确认服务端具体依据哪个协议特征判定。

用户继续要求提高浏览器一致性和降低再次封禁风险：API 保留已实测通过的头，HTML 不继承 JSON
Accept；沿用专用 Session/内存 Cookie；直连降级默认关闭；HTTP 429 立即暂停全部路径，
Retry-After 支持秒数和 HTTP 日期，并持久化到既有 blocked_until，允许超过本地退避上限。
没有更改 NAS 代理选择、增加 Cookie 文件或声称可以完全模拟人类。
