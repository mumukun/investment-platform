## 2. 这次相对前一版收紧了什么

1. **当天板块三项事实作为核心**：相对强度、上涨宽度、尾盘变化。历史板块持续性、资金和涨停梯队作为附加说明；缺少严格历史成分时，不把历史持续性设成硬门槛或补中性分。
2. **全天预选，尾盘定稿，预选榜不裁剪最终基础池**：上午、下午均按当时事实展示动态候选，14:30转入尾盘重点确认；此前展示过什么，与14:50谁有资格正式入选分开；阅读前5/20只只是页面摘要。
3. **资格审查与排序分开**：先通过数据、市场、板块、个股门槛，再排序。首版建议不叠加新A/B/C分档和任意风险加分表；风险用明确事实与硬否决说明，旧评分仅在旧历史中保留。
4. **不引入未具备的分钟量价条件**：首版不要求VWAP、每分钟站线上比例、20日同区间成交股数量比，也不把累计成交额增量叫作“缩量确认”。
5. **退出范围保持隔夜目标**：不采用外部方案的默认次日10点卖出、T+3持有、B优先及模拟账户仓位分配；不新增这些策略分支。
6. **增加板块作用对照**：后续用同一数据口径、入场/退出模型和成本情景检验板块过滤是否有效，不因为直觉就认定35分权重正确。

## 4. 每天怎样运行

以下时间是建议的首版工程安排，均为北京时间，不是盈利最优时点：

| 时间 | 行为 | 对使用者的含义 |
| --- | --- | --- |
| 盘前/此前完成日 | 准备证券规则、日线、当日可知分类 | 明确基础池、历史是否齐全 |
| 开盘后首批有效行情起（现默认约09:35起采集） | 展示上午动态候选，随有效快照刷新 | 可以提前观察，标明截至当时已满足/未满足条件 |
| 午间休市 | 保留上午最后有效候选，显示休市和行情时间 | 不将旧报价伪装成午间新行情 |
| 下午恢复交易至14:30 | 继续动态筛选与展示 | 新出现的机会仍可进入，早上入选不保证尾盘入选 |
| 14:30附近 | 保存尾盘比较基准，进入重点确认 | 候选继续变化，不形成参考入场 |
| 14:30—14:45 | 复用现有约5分钟快照检查变化 | 记录板块与个股的实际观测，不制造1分钟K线 |
| 14:48起 | 需要时启动一次有界的尾盘刷新；与同来源在途请求合并 | 保障正式截止前有真实、较新的数据，不进行全市场每分钟下载 |
| 14:50:00 | 截止用于正式信号的源时间和接收时间 | 之后收到的数据不参与本次选股 |
| 最晚14:51:00 | 在完整合格基础池重新核验、冻结、发布一个批次 | 一股一天一个正式信号；超时则该日无新计划 |
| 实际发布后至14:55前 | 等待满足价格范围的新报价 | 成立则形成参考入场，否则记录取消/未入场 |
| 14:55起 | 新入场计划到期 | 不拿当日收盘价补一个买点 |
| T+1连续竞价时段 | 观察可卖后的退出条件 | 触发、退出参考和真实成交分别表述 |
| T+1 14:56 | 未完成参考退出的样本形成到期退出意图 | 按统一收盘参考模型处理，异常保留待完成 |

14:30基准批次建议使用14:29—14:31实际收到的合格观测，在14:31关闭；源时间不早于14:28，其他交易/口径检查与正式批次一致。每条基准保存实际时间；后续称“14:30附近至尾盘变化”，不宣称每只股票恰好有20分钟连续行情。正式14:50截止仍严格固定。

仅依靠14:50才启动的常规采集，会出现数据在截止后才收到的问题，因此明确需要截止前的有界刷新。完成太晚就记录失败，不能顺延截止或改写时间。现有适配器的吞吐与时效是实施前提，不能由本设计宣称已满足。

### 4.1 盘中可以看见什么，尾盘什么才最终确定

- **上午和下午的动态候选**：使用当时已经收到的行情、此前完成日线和当日可知行业。按现有约5分钟全A快照更新，不要求每分钟重新下载全市场。展示现价/成交额、当前板块、结构位置，以及已满足、未满足和待尾盘确认的条件。
- 盘中先核验证券/历史/当前结构和当前板块相对强度/宽度；累计成交额达到1亿元且当前静态条件合格的列为“动态候选”。历史结构可观察但尚不足1亿元或静态条件未齐的另列“条件待满足”，明确原因，不提前宣称通过正式门槛。
- 预选不计算缺少尾盘证据的最终总分。列表先按已满足组/待满足组分开，各组依当前行业相对市场强度、个股相对行业当日涨幅降序，再按主支撑距离/ATR更小、实际成交额更大、代码升序排序。无合格行业或结构证据时只显示受限观察状态，不编造排序输入。
- 14:30基准尚未发生时，尾盘变化、高点保持等显示“待尾盘确认”，不用0、中性分或未来14:50数据代填。当前市场静态条件与尚未发生的尾盘市场条件分别展示。
- **14:30—14:50的尾盘预选**：在同一页面增加实际观察到的承接与板块变化，最终截止前仍然只是预选。上午名单可退出，新股票可进入；原因随当前事实更新。
- **尾盘正式名单**：使用14:50前已收到的数据，最晚14:51发布并冻结当时的入选依据和排序；正式发布后的现价、超价/失效、入场与到期状态可以更新，不能回写当时的信号。
- 正式名单发布后，动态观察区仍可随行情更新；之后新出现的股票只作观察，不补进当天已冻结的正式名单。正式名单不是等15:00收盘后才生成；收盘用于复盘和核验，不补造尾盘买点。
- 开盘前/非交易日显示明确日期的最近历史；采集失败标陈旧/不可用，保留最后健康结果。14:55后没有新的当天入场计划，不能把“仍在列表”解释为仍可参与。


## 5. 四道资格审查

### 5.1 数据、证券与流动性

- 使用真实交易日历和当天有效证券规则；非ST、非停牌、非无涨跌幅限制特殊阶段，涨跌停范围不从代码近似推断。
- 至少25个完成交易日的合格日线，供20日关键位及ATR比较；不足则观察，不用缺失值代算。25是特征需要，不是已验证的择股优势。
- 正式时点累计成交额：主板、创业板、科创板、北交所均≥1亿元，不预测全天成交额凑门槛；盘中尚不足门槛的只可列条件待满足；北交所正式计划仍禁用。
- 个股报价源时间距14:50≤60秒；市场/行业聚合所用源数据距截止≤180秒；源时间、接收时间均≤截止。
- 正式行业至少10个共同合格成员；市场/行业预期基础池覆盖率均≥80%。缺失数、分母和受影响范围展示。80%是工程候选值，尚未验证其对判断误差的影响，不冒充完整全市场。
- 累计高低、累计成交额、参考价、来源及复权尺度可核验，ATR20>0；无效或不一致数据隔离。缺历史、缺价格、缺必要基准不能靠机会分弥补。

预选母池按证券与可计算历史建立，最终重新检查所有基础池成员的当时成交额和价格条件，不只扫描屏幕榜单。个股成交额门槛不改变市场/行业统计分母。

### 5.2 市场是否允许新增隔夜计划

市场门禁只决定是否允许新增，不重复计机会分。建议初值：

- 沪深正常交易基础池有效样本上涨占比≥40%，涨幅中位数>-1%。
- 基准至正式截止，在共同合格成员上重算的涨幅中位数下降≤0.5个百分点。
- 已由合格来源、日期和截止时间核验的明确退潮/恐慌事实可阻断新计划；缺少情绪事实不填0、不宣称情绪已核验，也不替代以上必需价格门禁。

共同成员不足时是“市场数据不足”；价格门禁失败时是“市场条件不合格”。这两种情况与系统没运行、健康零候选分别记录。

### 5.3 当天板块是否有支持

统一以当时可知的同一主档行业体系为主；本次生产既有主档的体系待核验，不宣称已知申万一级。冻结预期成员，基准与正式两时点在共同合格成员上重算行业及对应市场，不能直接相减不同成员池的现成均值。相对收益、上涨宽度、累计成交额均显示实际覆盖。

首版三项硬条件，建议初值：

1. 当天行业等权收益高于对应市场等权收益。
2. 有效行业成员上涨占比≥55%。
3. 相对基准，行业相对市场优势下降≤0.5个百分点，上涨宽度下降≤15个百分点。

三项分别展示，综合分不能抵消宽度失败。不能把“排名较高”自动叫作普涨、资金流入或龙头板块。

近3日持续性、资金、涨停扩散和成交集中度只作背景。不能核验历史行业成分时，显示历史口径受限，不拿今天的成分倒算后作为硬门槛；其他辅助证据缺失不改变主规则分母或补分。

### 5.4 个股是否有合适的位置与承接

首版仍只有一种尾盘隔夜策略，下面是两条入选证据路径，持有期和退出相同，不按命中路径延长到T+3。

| 路径 | 核验规则（建议初值） | 可以怎样表述 |
| --- | --- | --- |
| 此前突破位附近承接 | 前5个完成日存在收盘突破此前20日最高收盘的交易日，且该日成交额/此前20日中位数≥1.15；当日最低价曾进入该关键位±0.5 ATR20，尾盘价在关键位至关键位+0.75 ATR20内 | 此前突破位附近、尾盘守在支撑上方；不能由累计最低价断言发生了某一分钟的回踩反转 |
| 强趋势均线附近承接 | T-1 MA5>MA10>MA20，MA20不低于3个完成日前；先检验MA10，再检验MA20；当日最低价进入对应均线±0.5 ATR20，尾盘价站在均线至均线+0.75 ATR20内 | 日线趋势合格、价格仍接近既有支撑；不自动贴“缩量回踩”标签 |

同一路径多个历史突破时选最近合格突破；两路径同时命中时以最近突破位为主支撑，并记录全部命中证据。所选主支撑无有效参与区间则暂缓，不事后挑另一个更有利的锚点。

共同行为约束：尾盘价≥此前MA20；截至当时日内价格位置≥60%；当日涨幅/实际涨停幅度<65%；14:30附近以来按统一约5分钟观测网格看到的高点至当前回撤≤1.5%，两端同口径累计成交额增量>0。相邻合格网格观测的源时间间隔需≤6分钟（为5分钟常规轮询留出抖动）；超过则不确认该股尾盘保持。盘中累计最高价不能代替尾盘观测高点。

这些条件检验“位置合适、截至目前有承接”，不证明明天上涨。今日第一次突破、远离支撑或缺形态历史的股票可展示观察原因，首版不额外建立第三种入场战法。

历史MA、关键位、ATR须先按截止前已可核验的复权桥接换到T日原始报价尺度，保存原始输入与桥接身份；无法对齐就阻断该股。不能把复权均线直接与未复权现价比较。

MA使用完成日收盘算术均值；ATR20为截至T-1的20个真实波幅TR的算术均值，TR=max(高−低, |高−前收|, |低−前收|)，不与Wilder平滑混用。日内位置=(现价−截至当时最低价)/(截至当时最高价−最低价)，高低相等或口径不明时不计算。涨幅位置使用当日有效参考价和实际涨停价，不拿除权前原始收盘价替代；所有收益比较与桥接须使用同口径参考价。

## 6. 怎样排序，怎样解释风险

通过四道门槛后才计算机会排序。建议继续用四项，首版研究权重为35/20/25/20；删除前稿未经验证的80/72/60参与分档与新风险加分表。分数仅用于排序，不是概率，也不单独产生参与资格。

| 维度 | 权重 | 必需输入 |
| --- | --- | --- |
| 当天板块支持 | 35 | 相对市场强度、上涨宽度、尾盘强度和宽度变化 |
| 个股主动性 | 20 | 当天相对行业涨幅、基准至尾盘相对行业变化 |
| 结构位置 | 25 | 与冻结支撑、此前MA20的ATR归一距离 |
| 尾盘承接 | 20 | 截止时日内位置、同口径尾盘成交额增量占比 |

换算建议固定为：C(x)表示截断到0—1；P(x)为基础池并列平均秩百分位，按(名次−1)/(样本数−1)计算。分母至少2，缺必需样本不产生可参与结果。

- 板块35：10×P(当天相对强度)+10×C((上涨宽度−40%)/40%)+10×C((尾盘相对强度变化+0.5个百分点)/1个百分点)+5×C((尾盘宽度变化+15个百分点)/30个百分点)。
- 主动性20：10×P(当天个股收益−行业收益)+10×P(基准至尾盘个股收益−同区间行业收益)。
- 结构25：15×C(1−|现价−主支撑|/ATR20)+10×C(1−|(现价−MA20)/ATR20−1|/2)。
- 承接20：10×日内位置+10×P((截止累计成交额−基准累计成交额)/截止累计成交额)。

行业百分位在同日完整合格行业池计算；个股百分位在通过数据/证券/流动性基础审查的同日股票池计算，不在最终入选前几名中排名。两端实际时间、共同成员和池身份随信号冻结。

并列时按主支撑距离/ATR更小、当日实际成交额更大、证券代码升序决胜。展示前5只是摘要，摘要同一行业最多2只；其余合格信号和全部排除原因保留，不从研究统计中删除，不把摘要截断当作组合收益模型。

风险区分别列“硬否决”和“提醒”：交易状态失效、数据陈旧、超参与范围、市场/行业失败等直接阻断；连板/近期加速、20%或30%品种波动、同行业集中、资金或历史口径不足据实提醒。不能让高机会分抵消硬风险，也不据此分配真实仓位。

## 7. 什么才算形成尾盘入场参考

发布时冻结主支撑L、信号价P、ATR20、证券真实参考价/涨停价、证据hash和14:55到期时间。建议有效价格下界为L按最小报价单位向上取整，上界为以下最小值按报价单位向下取整：L+0.75 ATR20、P×1.005、实际涨幅位置65%对应价格。若取整后恰在65%边界，则再向下一个报价单位；上下界无交集则无计划。

实际发布后先等第一条时间和数据质量合格的新报价：源时间和接收时间均晚于实际发布时间、14:55前、报价龄≤60秒。随后核验价格在冻结区间且证券/市场/行业事实没有已核验的硬失效，全部满足才作为共同入场参考。现有采集节奏无法得到新鲜事实时保持不可确认，不把旧值冒充当前。

第一条时点合格报价高于上界、低于支撑下界或发生硬失效，则取消该计划；纯缺报可等到到期。不回看选择更便宜报价，不用收盘价补入场。基准与新报价有来源切换时先校验累计和参考价口径，未核验则拒绝跨源比较。

展示“参考入场，未证明真实成交”，不显示“已买入”。新策略不会发出券商委托或承诺买得到；人工实际操作可能有延迟和价差。

每个共同entry_id冻结一次，两个退出对照共享。同股当日不重复生成；若默认固定退出账本仍有到期未完成样本，该股后续新信号可观察但不重复建立默认参考入场。研究动态模型的异常不得单独改变基线未来入场资格。

## 8. 次日怎样退出

### 8.1 默认基线：+3%触发，否则次日收盘

从真实下一个交易日连续竞价开始，按有序、实际收到的报价观察。首次观测现价达到经济口径入场基准×1.03时形成退出意图，以此后第一条新鲜合格报价作退出参考。触发不是成交，退出参考可能低于+3%。

T+1 14:56仍未形成退出参考时统一产生到期退出意图，包括此前触发但未等到下一报价的样本。普通完整、可核验交易日用已核验收盘价作收盘参考，明示集合竞价参考假设；无法核验时保留待完成。

旧“次日最高价触及便按+3%记账”保留在旧理论基准，不能与新报价路径结果混算。T日形成入场后不能在回放里当天止损。

### 8.2 次日冲高回落：独立研究对照

用户希望考虑冲高卖出；机制可以完整定义，但参数不能称为已确认默认。建议保留一组研究初值：浮盈达到2%后启动，之后现价≤截至当时已观测高点×0.99时触发，取下一条新鲜报价作退出参考。未触发同样按次日收盘基线。

仅使用可卖时段已经观测到的峰值，不使用未来全天最高价；2%启动后回撤1%的触发线约为浮盈0.98%，也不能保证实际锁定利润。这组参数与ATR移动退出均没有收益优势证据，首版不同时增加多个动态模型。

两个模型共用entry_id、报价路径、延迟与成本；动态结果仅在证据合格样本上配对比较，不倒过来调整入选名单。动态尚未交付时，固定闭环仍完整可用。

### 8.3 异常要如实留账

- 停牌、无成交、一字跌停或无法确认退出条件：保留到期未退出/不可验证，不假定收盘成交；之后处置另记真实处置日，不冒充T+1结算。
- 缺报价导致可能漏掉触发：标记不可评估，不宣称“没有触发”；若完整日最高价可独立证明固定目标从未触及，可单独核验固定收盘参考，动态仍不能凭日高重建路径。
- 不越过T+1收盘去寻找“下一条报价”补作当日退出；同分钟只有OHLC时，不选择有利先后顺序。
- 除权除息先核验价格尺度与经济基准，原始入场价不改；无法对齐则待完成。结果是经复权核验的价格参考收益，不宣称已经完成真实账户公司行为与现金分配账务。
- 所有亏损、未入场、未完成与缺数保留原因；默认模型的未完成不因改参数而消失。

## 9. 首版需要的数据改造边界

先复用已有适配器，补齐最小证据链：

1. 为本策略保留原始源时间、接收时间、来源/单位/参考价/修订身份，避免当前轮询丢失时间字段。
2. 保存14:30附近基准、尾盘正式输入、共同成员，以及约5分钟网格上必要的价格事实。固定快照不能被历史回填覆盖。
3. 信号发布后和T+1对正式候选目标每60秒记录一次实际新报价，用于入场与退出参考；全市场仍复用约5分钟快照和一次截止前有界刷新。
4. 对既有调度/在途请求做有界协调，逐批记录耗时、超时、覆盖及原因；无法处理的对象显式不可用，不靠静默裁剪到榜单前20来伪装容量足够。

这不是完整1分钟OHLCV服务，不包含所有股票多年分钟历史，也不构造不存在的VWAP。60秒是采样目标，不能把采样间未观测的触价当作已执行。数据龄、覆盖率和吞吐必须实际验证；本轮没有验证。

最脆弱的前提是腾讯/新浪现有能力能在截止前提供足够新鲜的横截面和后续报价。如果不满足，系统只能提供显式受限的观察名单，正式计划显示不可用；不能靠事后数据回填或擅自新增来源绕过。工程验证不通过即不宣称尾盘策略完成。

继续使用当前短线页面及公共个股详情，不新建一套交易终端：

| 区域 | 使用者需要看到 |

| 当天状态 | 上午预选/下午预选/尾盘确认/正式/到期/历史，截止与实际发布时间，行情时间、覆盖和失败原因 |

示例解释应类似：“所属行业当天跑赢市场，上涨家数达到门槛，尾盘未明显转弱；个股仍守住此前支撑，价格在参与范围内。”每个判断后附实际数值、日期和时刻，不用“AI看好”“资金吸筹”等不可核验结论代替。

### 10.1 每只股票的收益：默认直接展示的主表

用户进一步澄清，首先要看到的是“符合条件的每个股票的收益”，而不是只看到胜负率。因此逐股收益主表为首版核心功能，默认展开；统计卡片是这张表的汇总入口，不要求先点击卡片或手工选择股票才建账。

- **覆盖所有正式股票**：当日正式名单每股一行，同一股票多路径命中只保留一个稳定signal_id及辅助标签；不局限摘要前5只、盈利股票或用户手动选择。入场后关联entry_id。所有行长期保留，按入选日倒序分页，可按日期、股票和结算状态查询。
- **默认尾盘入场**：每行按第7节的统一规则自动等待并记录合格尾盘参考价，无需用户确认真实买入。未形成合格入场参考时保留该股票、价格条件及未入场原因，收益为“—”，不假造收益。
- **主要列**：入选/入场日期、股票名称与代码、主导结构、尾盘参考买入时刻和价格、最新合格参考价与行情时刻、当前浮动收益率、次日参考卖出时刻/价格、已结算收益率、胜/负/平或未完成状态。最终退出前两列卖出与已结算收益为空；可以看到已入场股票的浮动表现。
- **两种收益分清楚**：当前浮动收益按最新可核验价格相对同一经济口径入场基准计算；已结算收益按第8节实际取得的退出参考计算。未扣费、同价尺度时公式为(参考价/参考入场价−1)×100%。除权按既定桥接处理；行情缺失或陈旧时注明实际时刻/原因，不用0代替。浮动收益不计胜负，退出后最终收益冻结，不随后续股价改变。
- **盘中与历史**：上午/下午预选先展示当日涨跌及待尾盘状态，不称已买入收益；形成尾盘参考后才有该次入场的浮动收益。默认主表为截至观察日的完整当前规则历史，页面分页不丢其他股票，历史查看不使用观察日之后的价格。
- **异常仍可查**：缺报价、停牌、退出受阻、复权未对齐、次日未到等都保留该行及原因；即使有最新价对比，也不能拿浮动收益替代无法评估的退出结果。北交所研究观察单列，不伪造正式入场。
- **汇总可核对**：胜负率、盈利/亏损/持平笔数只由同口径已结算行计算；点击卡片只是筛选对应行，主表本身始终可直接打开。

### 10.2 短线胜负率：逐股收益的汇总

用户明确要求短线具有类似波段的胜负率统计，且默认尾盘买入。这项功能随首次固定退出闭环交付，不放到动态退出研究阶段。

**默认统计口径**：新规则下的尾盘参考入场 + 固定+3%触发/次日收盘退出 + 未扣费用的价格参考收益。所有正式信号先建立跟踪行；只有发布后、14:55前满足第7节新报价与价格条件时，才自动关联参考入场记录，无需手动勾选才统计；不读取真实持仓，不产生券商委托。没有合格报价的正式候选记录为待入场或到期未入场，不自动按收盘价买入。

上午/下午预选的涨跌不作为买入收益，盘中被多次选中也不重复计交易。默认总体包含所有按规则形成的尾盘参考入场，不只统计页面摘要前5只或当前分页。

**胜、负、持平以退出参考收益判断**：

| 项目 | 定义 |
| --- | --- |
| 已结算S | 按本退出版本取得合格T+1退出参考，收益可以可靠计算的笔数 |
| 胜W | S中退出参考收益>0的笔数，没达到+3%但最终盈利也算胜 |
| 负L | S中退出参考收益<0的笔数，不以是否触发某条风险标签判负 |
| 持平F | S中退出参考收益=0的笔数，不算胜，也不并入负 |
| 胜率 | W/S |
| 负率 | L/S |
| 持平率 | F/S |

按冻结的计价版本和未做展示舍入的收益判定正负；百分比仅展示时舍入。S=W+L+F；无已结算样本时三率均为null，页面显示“—/暂无已结算”，不能显示0%冒充全败。

合成示例：20笔已结算中12胜、6负、2平，胜率60%、负率30%、持平率10%。未入场或仍待完成的记录另列，不在这20笔分母中。“+3%触发退出占比”单列，是已结算中因目标触发而取得退出参考的笔数/S，不等于胜率；触发但尚无合格退出参考的仍不算已结算。

**完整分母与异常**：正式信号=已参考入场+尚在有效窗口等待入场+已明确未入场；已参考入场=已结算+尚不能按T+1口径结算。后者分别显示待次日、退出受阻、缺报价/不可评估、复权待核验及到期未完成原因。不可评估数是未结算的子集，不能再次相加。延迟处置有单独实际日期与收益，不补成原T+1结果，也不让失败样本消失。这里的未结算表示没有可靠T+1结果，不等同于真实账户仍持仓。

**显示与核对**：

- 默认截至所选观察日、当前尾盘规则版本的全部历史；展示统计范围、入场/退出/费用口径和样本数。明细分页或点击某个胜负卡片不改变顶部总统计分母。
- 卡片显示正式信号、参考入场、已结算、待完成/不可评估、未入场，胜率/负率/持平率及胜负平笔数，平均/中位收益，目标触发退出与次日收盘退出笔数。
- 像波段一样，点击盈利/亏损/持平、已结算、待完成等卡片可打开对应明细。明细包含股票/买入日、参考入场时刻和价格、退出规则/时刻/价格、收益、胜负结果或未完成原因、原始入选依据；支持股票详情和历史查询。
- 按入场冻结的主导结构路径、行业、交易板块分别分组；多路径命中总体只计一笔，每个分组维度各自不重复。北交所仅观察和盘中预选不混入正式样本。
- 固定与动态退出独立统计，不相加为两笔交易；动态比较使用共同entry_id样本。旧收盘模拟买入结果通过独立历史入口查看，不能并入新尾盘默认胜率。
- 成本敏感性另列；若查看扣某一成本情景后的胜负，必须重新按该情景收益分类并标明费用，不能把未扣费胜率叫作实际净胜率。分组小样本始终显示笔数，不宣称未来胜率。

源码复用依据：Provider的short_tracking.stats已经计算wins/losses/flat/win_rate与分型收益，Consumer有ShortEffectTracking和计数一致性验证；波段SwingSelectionView已有点击指标核对历史的交互。重构增加尾盘入场证据、负率/持平率与完整信号/未入场覆盖、新账本版本和明细筛选，沿用现有页面与Provider统计职责，无需新建统计服务或账户。

## 11. 如何判断重构有没有价值

**先证明工程真实，再检验策略有效。**没有严格尾盘历史快照及收到时间时，从新版本开始积累证据，不用日线倒造多年尾盘买点。

必须报告：

- 应运行日数、成功/零候选/失败/超时、基础池与覆盖、未入场及原因。
- 参考入场数、退出数、到期未完成与不可评估数；按第10.2节显示胜/负/持平笔数、胜率/负率/持平率与已结算分母；均值、中位数、盈亏分布、下行尾部、隔夜低开与已观察浮盈回吐。
- 分结构路径、市场状态、行业及板块；北交所观察另列，不混入正式结果。
- 毛参考收益，以及往返成本0.1%/0.2%/0.4%情景敏感性。这些不是用户真实佣金或成交成本，不新增账户/数量只是为了算一条“实际净收益”。

三项比较：

1. 固定+3%与冲高回落：共享同一入场与共同路径，做配对比较，披露覆盖差异。
2. 有/无当天板块过滤：冻结同一基础池、其他规则、参与窗口、退出与成本，分别产生名单并比较；它们不必有相同成交样本。作为不影响正式信号的研究分支，验证板块价值。
3. 新旧策略：各自入场和计价含义单列，不能把旧账本收益拼成新版本曲线，也不把完整日持有指数当作唯一隔夜基准。

参数先冻结，按时间顺序做样本外检验，登记尝试过的配置；按交易日/行业考虑相关性，不把同日多只股票当大量独立证据。不得只保留表现最好的一组，也不机械承诺200笔或30天就证明盈利。追加未来数据后，过去信号、原始入场和证据必须不变。

## 12. 仓库、接口和存储怎么改

仅在后续获实施授权时修改业务仓库。架构继续为：

```text
已授权腾讯/新浪 + 既有日线/证券规则/当日分类
    → stock-analyzer：证据 → 四道门槛 → 排序/计划 → 参考跟踪/统计
    → 版本化只读API
    → investment-research-dashboard：展示、历史归档与对照
```

stock-analyzer负责计算和唯一事实，Dashboard不重新算策略、不跨仓读库。继续采用前稿的新旧契约并存提案：

| 只读路径 | 新契约 |
| --- | --- |
| `/api/integrations/investment-dashboard/short-selection/tail` | `investment-dashboard-short-tail-selection-v1` |
| `/api/integrations/investment-dashboard/short-selection/tail/tracking` | `investment-dashboard-short-tail-tracking-v1` |

携带strategy_id、rules_version、阶段（动态预选/尾盘确认/正式）、盘中已满足/未满足/待确认条件、当次真实数据时间、signal_id、数据截止/源/接收/发布时间、质量、分母、排序分项、风险事实、参与范围、entry_id、pricing_model、exit_rule_version、路径覆盖及待完成原因。统计响应显式提供formal_signals、entry_pending、not_entered、entries、settled、unsettled、wins、losses、flat、win_rate、loss_rate、flat_rate、return_mean/median、未结算原因与样本可评估覆盖；率为0—1的可空数值，收益为百分数，不能用当前页行数充当总体。机会分没有概率含义，不保留新策略未采用的A/B/C档位。契约版本与规则/应用/计价/退出版本各自独立。

建议未实现的新策略初始身份仍为`short-tail-overnight-v1`，规则`short-tail-rules-v1`，计价`short-tail-reference-v1`；退出分别为`late-nextday-observed-tp3-v1`与`late-nextday-observed-trail-a2-d1-v1`。设计稿v1.4不是生产规则v1.4；若这些身份已在别处实际产生过样本，实施时必须新增规则身份，不能覆盖。

存储复用`short_simulated_trade`和其evidence/版本隔离，建议加法增加两张小表：

- `short_tail_run`：基准/正式批次、成功/健康零/失败、成员、两端原始输入、复权桥接、冻结信号。signal_snapshot不可改；entry_resolution等后续阶段只追加，不借更新结果改写选股依据。
- `short_tail_observation`：正式候选的不可变有序报价与缺口，来源、源/接收时刻、口径、修订身份和幂等事件身份齐全。约5分钟必要网格输入可在批次证据保存，不复制全市场逐笔库。

旧`short_close_run`、旧接口、旧统计保留原含义，Dashboard使用独立`short-tail-selection`归档域。查询保持Bearer只读；失败保留最后健康历史并标明旧日期，不把上次信号伪装成今天的新计划。

涉及Provider引擎/运行时/存储/跟踪/API和Consumer适配/模型/归档/短线页及测试文档，预计超过8个文件。新增服务、数据商、凭据、账户、顶层页面和用户配置项均为0；不引入模拟券商、订单网关、相关性组合和完整资金账务。

## 13. 实施交付与验收

推荐分成两次可独立使用的交付，不把“先调查数据”单独当功能交付：

| 交付 | 完整包含 | 完成后能做什么 |
| --- | --- | --- |
| 首次：全天预选与尾盘固定退出闭环 | 最小数据证据补齐、上午/下午动态候选和尾盘确认、市场/板块/两种结构、正式信号、价格窗口、固定+3%/次日收盘、异常、默认展开的逐股收益主表、尾盘胜负率卡片/分组/可核对明细、同页展示和新旧隔离 | 可以完整研究尾盘至次日的固定规则，无需动态模型也能使用 |
| 后续：共同路径动态对照 | 在相同entry_id上增加研究动态退出、缺口判定与配对统计，并加入板块过滤研究对照报告 | 比较退出方式与板块规则的作用，不改基线历史 |

必要验收：

| 情况 | 必须结果 |
| --- | --- |
| 上午/下午查看 | 展示截至当时的数据与候选；尾盘条件标待确认，不泄漏未来数据 |
| 上午不足1亿、下午达到1亿 | 从条件待满足重新核验；不得提前按预计全天成交额通过 |
| 四板块成交额边界 | 1亿元通过该项，0.99亿元不通过正式流动性门槛；北交所仍仅观察 |
| 14:30未入榜、14:50满足条件 | 仍能从完整基础池被选出 |
| 午休、采集失败、正式后新增观察股 | 分别显示休市/陈旧或不可用/仅观察，不改冻结正式名单 |
| 同一源快照重复读取 | 不增加确认、不产生重复信号/入场 |
| 源时间或收到时间超过截止 | 不进入正式信号；晚于14:51无新计划 |
| 缺历史/VWAP/辅助资金 | 缺必需历史阻断个股；不要求VWAP；辅助缺失不补分 |
| 降低个股成交额门槛 | 不改变市场/板块统计分母 |
| 行业分类不一致、成员变动 | 不混接，按共同成员重算；覆盖不足隔离受影响行业 |
| 首个新报价超价、未报价到期 | 取消/未入场，不补收盘买入 |
| 入场后下跌或次日低开 | 样本保留，不能T日卖出或按止损线假结算 |
| 缺路径、停牌、无法核验退出 | 不可评估或待完成，失败样本不消失；胜负率分母不含未结算，但完整覆盖数展示 |
| 无已结算/全部持平/有深亏样本 | 无样本显示—；持平不算胜也不算负；深亏不得从分母删除 |
| 上午候选/重复刷新/摘要和分页变化 | 不形成盘中买入收益，不重复交易，不改变总体统计分母 |
| 每个符合正式条件的股票 | 自动产生稳定跟踪行，未入场/亏损/缺数均保留，默认可直接查看，不依赖点击卡片 |
| 浮动收益与已结算收益 | 前者按真实最新报价更新且不计胜负；后者按退出参考冻结，陈旧/缺失与未来价格不混用 |
| 胜负卡片与明细、旧/新账本切换 | 分子分母及合成例计数一致，点击可核对；默认尾盘，旧收盘及动态结果不混算 |
| 除权与历史修订 | 原始依据不变，基准单独核验，必要时阻断 |
| 配对对照 | 同entry_id、同数据/延迟/成本；板块消融研究与正式输出隔离 |
| 上游失败/不兼容与历史读取 | 显式降级，保留健康历史；历史GET不采集/回填写入 |

实际实现后，Provider执行受影响pytest、compileall和隔离PostgreSQL的增量DDL幂等/真实SQL测试；Consumer使用Provider真实生成的fixture执行解析/归档/契约回归、受影响pytest、Ruff、Vitest及构建，人工核对时间/状态/价格/解释。本次实施证据见Change记录；合成fixture与真实SQL测试不冒充收益回测。

仅修改的业务仓库按最终兼容范围MINOR演进，Provider先于Consumer；回退精确旧应用保留新增表与证据、旧接口继续可读，不删历史。Commit、Push、PR、Merge、Tag、生产部署分别遵循授权；当前未获得这些授权。

## 14. 这份方案的结论与边界

推荐首版为：**现有数据能力上的尾盘隔夜研究闭环：先审数据与市场，再看当天板块，随后核验个股结构、排序和价格范围，最终用固定次日退出建立可追溯结果。**冲高回落是同样本研究对照，历史资金背景与其他战法不成为首版依赖。

最小替代是只降成交额并继续旧综合评分/收盘账本，改动少但不能回答尾盘实际何时可参与、次日如何兑现，因此不满足完整目标。整套移植外部分钟/组合方案则超出当前数据与产品边界。

成交额和隔夜目标已由用户确定；本文其他阈值、权重、时间和路径是具体的建议研究配置，并非已批准或已验证的盈利参数。若数据能力不达标，工程应如实显示不可用；若样本外无优势，结论应是尚未证明有效，不能继续加条件直到曲线好看。
