# 科技看板数据与接口设计

日期：2026-10-15。版本：1.0。对应 [PRD](tech-board-prd-v1.md) 与 [数据源核查](tech-board-data-source-audit-2026-10-15.md)。用户随后已授权首版开发与本地提交；本文件记录实现边界，具体契约同步维护在各业务仓库docs/tech-board.md与docs/technical/tech-board-contract.md。当前已本地提交、待验收，未推送或发布；提交SHA见Change记录。

## 设计决策

推荐复用stock-analyzer行情所有权和Dashboard本地投影，新增模块级版本化契约，不新建服务。最小版本只接入有证据的具名标准指数及其成员，用户指定证券另设关注；缺口保留原因，不增加本地财务统计引擎。

数据源预算为零新增订阅费：不接入 Tushare，不购买积分、付费接口或付费采集服务。来源收费或停止公开访问时保留最后有效快照并标明状态，不自动切换付费服务，不从个股数据补算板块。

最脆弱的前提是公开网页或接口能够长期保持结构与可用性。本设计以具名来源独立降级、最后有效快照和精确身份映射应对；接口失效时缩小当前可比较范围，不切换到另一条“差不多”的指数。

```text
国证官方：身份 / 成分 / 已验证指数报价与日线
腾讯优先 / 新浪备用：已验证的精确证券报价
同花顺公开免费数据：仅在日期、完整性及稳定访问验收后进入
                        │
                        ▼
                stock-analyzer
         来源映射 → 原始事实 → 来源快照与归档
                        │
              版本化只读Bearer契约
                        ▼
                Dashboard后端
          本地投影 → 事实摘要 → 页面查询
                        │
                        ▼
                 科技看板前端
         原始值排序 / 来源展开 / 关注 / 历史回看
```

stock-analyzer拥有来源事实、指数身份、成员与归档。Dashboard不访问上游数据库；个人显示偏好首版保存在浏览器，研究记录继续由Dashboard拥有。marketNewsFeed不新增依赖，也不修改已有新闻采集。

## 身份与来源映射

来源对象以“发布方 + 原始代码 + 市场 + 价格/全收益类型”标识，名称用于显示而非主键。产品目录与行情对象分离：目录“算力租赁”不能指向国证算力并伪装成精确覆盖。

| 对象 | 必须保留的信息 | 约束 |
| --- | --- | --- |
| 指数身份 | 发布方、原始代码、全称、简称、市场、收益类型、编制资料链接 | 不把宽基、综合主题、细分行业互相改名 |
| 平台映射 | 行情平台、平台代码、网页路由ID、对应身份、验证证据、能力 | 同花顺页面308832与行情885959分字段保存 |
| 证券身份 | 稳定证券ID、来源代码、交易所、市场、币种、名称 | A/H不同证券分开；映射用已核验证券主数据，不凭名称相同合并 |
| 产品目录 | AI硬件环节、显示顺序、接入状态、精确映射或缺口原因 | 人工维护导航不产生正式成员关系 |
| 用户指定关注 | 用户来源、证券ID、显示顺序 | 与第三方成分分离，不形成板块统计 |

接口仅接受注册对象ID，不允许把用户输入的URL直接交给采集器，避免把详情查询变成任意外部请求。

## 逻辑数据模型

以下是数据所有权与字段设计，不要求每个逻辑对象单独建表。首版在Provider新增tech_board_fact/tech_board_run，Dashboard复用Snapshot/SyncState，不新增Dashboard migration，不修改旧模块历史数据。

| 逻辑对象 | 核心字段 | 所有者与写入方式 |
| --- | --- | --- |
| 来源注册 | 发布方ID、对象代码、平台映射、能力、原名、收益类型、证据引用 | Provider维护小规模注册目录 |
| 来源事实快照 | 对象ID、种类quote/bar、原始字段、字段单位、源时间、业务日、采集时间、来源、原始响应哈希 | Provider幂等写入；保存原值和修订关系 |
| 成员快照 | 发布方对象ID、来源数据日期、观测时间、成员代码、权重原值、完整性、分页证据、版本ID | Provider完整回读后原子发布；失败不替换健康版本 |
| 收盘归档 | 市场、业务日、行情快照引用、成员版本引用、比较集合、暂定/已核验状态、修订时间 | Provider保存已取得的第三方事实，不从成员重算指数 |
| 页面投影 | 契约版本、Provider快照引用、同步时间、质量、目录、有效指数、来源缺口 | Dashboard复用Snapshot/SyncState边界 |
| 事实摘要 | 引用快照ID、比较范围、模板版本、语句及其字段引用 | Dashboard依赖同一投影生成，不跨快照取值 |
| 个人偏好 | 收藏证券/指数ID、固定目录、显示顺序 | 浏览器本地；无跨设备承诺 |

行情源时间不一定等于最后成交时刻，成员文件日期也不一定是成员调整生效日。必须分别保留source_data_date、source_time、observed_at；有效日未发布时记录未知，不把采集日填成生效日。

### 原始涨幅与单位

板块涨跌幅只来自第三方明确发布字段。例如国证percent为比例、腾讯zdf或报价中的原始涨跌幅为百分数，标准化时只做单位转换并保留raw值和raw单位。

禁止用价格重新计算百分比、平均个股涨幅、生成等权/市值加权指数、合成上涨比例、估算资金净流入。排序和数量完整性检查是展示/质量操作，不产生替代行情。

实时接口的close=0本次是未提供有效日线收盘的情况，保存为来源事实但不映射成可绘制OHLC收盘；日K只取已经验收的原始bar。成交额或成交量单位未知时不显示该字段，不根据数值大小猜单位。

### 成员完整性

1. 初次接入核对发布方身份、分页约定、唯一证券代码、数据日期和已发布的样本规模规则。
2. 不把默认页data.total直接视作完整总数：本次国证默认页20条，扩大rows后可取得40/42/50/50条；PCB另外读取第二页验证截断风险。
3. 动态样本规模按发布方规则处理，例如存储芯片上限50只、不足时按实际数量，42只不能直接判缺8只。
4. “--”权重保留缺失，不补0、不归一化。没有可靠权重不影响读取发布方已经计算的指数。
5. HTTP401/403、空页、重页、无终止依据或异常规模变化不发布为完整新版本。保留上次完整版本并显示核验状态。
6. 历史日期只关联当时已取得的版本；最新成员接口没有纳入/剔除日期时，不能构造历史有效期。

## 拟议接口边界

新增独立契约investment-dashboard-tech-board-v1，避免修改全球看板现有只接受腾讯/新浪的来源约束，也避免复用旧行业计算契约的衍生指标含义。

| 层 | 拟议只读接口 | 职责 |
| --- | --- | --- |
| Provider | GET /api/integrations/investment-dashboard/tech-board | 目录、具名指数报价、可比较范围、快照与缺口 |
| Provider | GET /api/integrations/investment-dashboard/tech-board/boards/{id}/members | 指定完整成员版本和成员行情状态 |
| Provider | GET /api/integrations/investment-dashboard/tech-board/boards/{id}/history | 原始日线、保存的报价采样或收盘归档，分别标注 |
| Dashboard | GET /api/v1/tech-board | 从本地投影返回页面概览和事实摘要 |
| Dashboard | GET /api/v1/tech-board/boards/{id}/members | 本地成员查询与分页 |
| Dashboard | GET /api/v1/tech-board/boards/{id}/history | 带实际业务日期的本地历史查询 |

请求读取缓存，不因前端排序、收藏或刷新直接抓取第三方。成员及历史按需分页，避免首页发送所有指数的完整分时。现有鉴权和源地址配置复用；不新增公开写接口，不修改现有接口含义。

每个响应需要携带契约版本、真实/Mock标志、对象身份、源日期和时间、同步时间、来源平台与发布方、质量、成员完整性、原始单位、能力缺口及快照引用。契约版本与来源映射版本、摘要模板版本分别管理，不与应用版本绑定。

## 排名与摘要的数据约束

排名按原始涨跌幅排序，比较集合包括发布方或分类体系、市场、价格/全收益类型、业务日期和盘中/收盘模式。国证主题指数与同花顺概念、港股与A股、今日盘中与昨日日线不得混排。综合算力指数在同一体系中可以并列展示，但不称作与PCB互斥的行业，也不合并成交数据。

一次摘要只引用一个可比较投影快照。没有三条就少写，只有一条不输出相对比较，全部下跌时使用“跌幅较小/较大”。源数据陈旧时旧榜单、旧摘要整体以原日期展示，不在当日标题下混用。

若第三方指数有效、成员个股报价部分缺失，原始指数值仍由来源负责；本地不通过采集比例改变指数。成员表明确缺失项，成员版本失败时显示最后有效版本日期。

首版不输出上涨扩散、轮动传导、资金方向或原因归因。未来只有同一来源直接提供且定义通过核验的字段才可显示；不能把AI文字生成作为缺数据的补丁。

## 更新、归档和失败处理

调度建议见PRD。所有循环位于现有Provider/Consumer进程中，不新建容器或消息队列。

- 报价按对象、来源、源时间去重；同一证券属于多条指数时共享行情请求和缓存。源时间不变不每分钟伪造一个新点。
- 有发布方原始分时才称“分时”；本地记录的离散报价称“报价采样”，跨日、长断档或不兼容来源切换时分段。
- 源行情日期按对应市场处理。国证日线时间戳转换Asia/Shanghai后取业务日，不能用UTC日期截断。
- 收盘归档保存观察到的状态与修订；日线晚到后增补原始事实，不覆盖此前“当时看到了什么”的记录。
- 暂不引入自动清理历史的破坏性任务。实现时测量写入量与查询负载，后续有明确保留策略再处理采样清理。
- 外部请求使用有限超时与现有退避机制。一次失败不触发全目录重拉；收到拒绝不循环绕过。免费接口没有本项目确认的SLA。
